# 接力鑰匙 美術規格

> index.html 必須宣告 `<meta charset="utf-8">`, 否則 art.js 裡的中文字(HUD、說明頁)在 file:// 下會變亂碼。
> 載入方式: `<script src="game/art/art.js"></script>`(非 module), 之後用全域 `window.Art`。

## 形狀語言

圓角剪影的角色 + 方正的機關; 平塗、深色描邊; **實線 = 實體、虛線 = 可穿過 / 不是實體**(幽靈外框、單向平台底邊、打開的門與鎖、說明頁看不見的東西)。

## 理念落實

- P0 辨識度先於好看: 每種機關一種顏色 + 一種內部記號(升降台 = 向上箭頭、門 = 門柵、鎖 = 鑰匙孔), 不加裝飾性特效
- P1 迫切度: 全畫面最強的視覺(青色整圈框 + 暫停條)只給「瞄準暫停中」; 可鉤發光是場上唯一帶外光的角色元素; 背景軌道、點點壓到 0.12~0.22 不透明
- P2 規則存在就要看得見: 幽靈只有頭頂能站 → 頭頂畫一條不透明亮條; 單向平台 → 虛線底邊; 坑 → 地面在 x 600 斷開、坑底漸暗; 升降台會跑的範圍 → 背景綠虛線軌道; 物件畫面邊界等於判定框(Node 量過, 全在 size 內)
- P3 一本字典: 鑰匙原位、角色手上、HUD 欄位、說明頁都是同一個金色鑰匙路徑; 開關與它控制的物件同色, 鎖與鑰匙同色; 說明頁一律呼叫遊戲內畫法並給合法 state(例: 第 4 頁幽靈離地 150 < 跳躍高 168)
- P4 兩條通道: 玩家 vs 幽靈 = 不透明實線 vs 半透明虛線 + 頭頂條; 門 vs 鎖 = 紫 vs 金 + 門柵 vs 鑰匙孔; 開 vs 關 = 實心 vs 虛線框; 開關壓住 vs 放開 = 高度(6 vs 10 px)+ 亮度
- P7 掙得版面: 路線不加起點標示與分色, 只在終點一個小三角表示方向; 蓄力不另畫蓄力條, 箭頭長度就是力道
- P9 最混亂的一刻: 三代回放同框時, 每隻剪影肚子上有代數數字; 手上的鑰匙在幽靈身上也是不透明的, 疊在一起仍找得到誰拿著
- P13 事件排隊: 本作沒有事件提示, 撿鑰匙、接鑰匙、開鎖都只改物件本身的長相(手上多一把、鎖變虛線), 不會同時冒出字
- P15 強度對份量: 一般狀態只換物件本身; 只有「時間暫停」這種全場狀態用全畫面框
- P17 進度分工: 鉤爪剩餘用 2 個可數圖示(不寫數字); 蓄力只用箭頭長度, 蓄滿時箭頭轉白加光(數字給不了的「到頂了」)
- P18 不只存在一瞬: 「我有沒有鑰匙」除了手上, HUD 有常駐的鑰匙欄(空 = 虛線空格)
- P19 貼著物件: 可鉤發光長在幽靈輪廓上; 帶鑰匙畫在角色手上; 代數寫在身上
- P21 對錯會分岔的例子: 說明第 2 頁「跳不上去 ✕」與「掉坑 ✓」並排; 第 8 頁把「升降台實際在底」與「幽靈腳下的虛線升降台」同框, 錯誤理解(幽靈自己會飛)與正確規則(看不見的 1 號開了電梯)畫出不同的圖

## 物件表

所有座標: 物件左上角(另註明者除外)。每個函式自己 save / restore。

| 物件 | 函式 | state 欄位 | 各狀態視覺 |
|---|---|---|---|
| 背景 | `drawBackground(ctx)` | — | 深藍漸層 + 固定點點 + 升降台綠虛線軌道(x 486 / 594, y 780~1200)+ 坑(x 600~720, y 1200~1280)漸暗。每幀最先畫 |
| 平台 | `drawPlatform(ctx, {x, y, w, h})` | x, y, w, h | `h ≥ 48` 畫成實心地面(石塊 + 亮頂邊); 否則畫成單向平台(實心頂面 + 半透明身體 + 虛線底邊) |
| 尖刺 | `drawSpike(ctx, {x, y, w})` | x, y, w | 紅色三角齒(每齒約 12 寬)+ 暗紅底座, 高 24 |
| 開關 | `drawPlate(ctx, {x, y, pressed, kind})` | pressed: bool; kind: `'lift'` / `'gate'` | 放開: 凸起 10 px, 暗底 + 彩色框 + 種類記號(lift 向上箭頭 / gate 兩根門柵); 壓住: 降到 6 px, 整塊亮色 + 外光 + 白亮線 |
| 升降台 | `drawLift(ctx, {x, y, active})` | y = 頂面(780~1200); active: bool | 未驅動: 暗綠 + 綠框 + 淡箭頭; 驅動中: 亮綠 + 外光 + 白色向上箭頭 |
| 門 | `drawGate(ctx, {x, y, open})` | open: bool | 關: 暗紫柱 + 兩根亮紫門柵 + 頂底蓋; 開: 只剩頂底蓋 + 淡紫虛線框(可穿過) |
| 鎖 | `drawLock(ctx, {x, y, open})` | open: bool | 關: 金色柱 + 深色鑰匙孔; 開: 只剩頂底蓋 + 淡金虛線框 + 中央打開的掛鎖 |
| 鑰匙(原位) | `drawKey(ctx, {x, y})` | x, y | 金鑰匙 + 淡金圓底 + 外光。只在還沒被撿走時呼叫 |
| 終點旗 | `drawGoal(ctx, {x, y})` | x, y | 旗桿 + 黑白方格旗 |
| 幽靈路線 | `drawGhostPath(ctx, {segments})` | segments: `[[{x,y},...], ...]`, 每點為碰撞框中心 | 淡藍點線, 段與段不連線; 只在最後一段終點畫一個小三角(方向)。回放時不呼叫 |

| 鉤索 | `drawHook(ctx, {x1, y1, x2, y2})` | 角色中心 → 被鉤幽靈中心 | 白線(深色襯底)+ 終點爪頭 |
| 玩家 | `drawPlayer(ctx, {x, y, facing, state, gen, hasKey})` | state: `idle` / `run` / `air` / `aim` / `launch` / `dead` | 不透明藍 + 深描邊, 無頭頂條; aim: 外圈白框、眼睛往上看; launch: 身後白速度線; dead: 灰身 + X 眼 + 腿張開; hasKey 同幽靈; 肚子寫 gen |

| 說明頁 | `drawGuidePage(ctx, {page})` | page: 0~7 | 整頁自己畫(背景、頁碼、標題、說明文字、示意圖、頁碼點、「空白鍵 下一頁 / 開始遊戲」), RD 只要清畫布後呼叫它 |

### HUD 細節(drawHud)

- 上方 0~100 深色帶。左起: 「第 N / 3 代」+ 3 個小人(目前這代 = 實心藍、上一代 = 幽靈、更早 = 淡虛線〔已消失〕、未來 = 灰空框)→ 「鉤爪」2 個圓圖示(剩 = 青色實心、用掉 = 虛線空圈)→ 「鑰匙」欄(有 = 金框 + 鑰匙、沒有 = 虛線空格)→ 右上「R 整關重來」
- 第二行: 平常是操作提示; `aiming = true` 時換成青色提示條「時間暫停 Z 彈出 / X 取消」, 並在遊戲區(y 100~1280)外圍畫一圈青色框 + 極淡青色罩 = 時間停住
- `phase = 'win'`: HUD 帶換成「過關!」「三代合力回放」+ 3 個幽靈小人 +「空白鍵 重來」, 遊戲區不蓋(回放照常畫)
- `phase = 'lose'`: 全畫面深色罩 +「失敗」「三個人都倒下了」「空白鍵 重來」
- `phase = 'dying'`: 同 play, 無額外疊加(死亡演出由 drawPlayer 的 `dead` 負責)

## 繪製層級(由下到上, RD 照這個順序呼叫)

1. drawBackground
2. drawPlatform(地面、平台一、平台二)
3. drawSpike、drawPlate、drawLift、drawGate、drawLock、drawGoal、drawKey
4. drawGhostPath
5. drawGhost(回放時 3 隻)、drawHook(幽靈紀錄中的鉤索)
6. drawHook(玩家的)、drawPlayer
7. drawAim(瞄準中)
8. drawHud(最後; aiming 的框與 lose 的罩都在這一層)
