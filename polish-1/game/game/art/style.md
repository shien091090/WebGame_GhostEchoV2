# 幽影接力 美術規格(polish-1 / 打磨版六關)

> index.html 必須宣告 `<meta charset="utf-8">`, 否則 art.js 的中文字串在 file:// 下會變亂碼。
> 用法: `<script src="art/art.js"></script>` 後取用全域 `window.Art`。全部函式自帶 save / restore。
> 沿用 deepen-2 game-c「起跑哨」的色票、形狀語言與物件畫法; 本版新增: 牆、鎖、鑰匙(含手上鑰匙)、翹翹板、HUD 新欄位、關卡卡片、解鎖頁、全破畫面; 說明頁改為 5 頁。

720 × 1280。HUD 佔上方 y 0~100(drawHud 自己畫底板), 遊戲區 y 100~1280。

色相分配(色相 / 灰階): 紅 0° / 130(危險)、**橘 30° / 161(鑰匙、鎖)**、金 46° / 207(終點)、黃綠 90° / 208(鉤爪)、青 186° / 168(升降台)、淡藍 221°(幽靈, 低飽和半透明)、洋紅 289° / 150(門)。紅只給危險, 不挪作他用。

**鑰匙色的取捨**: 色環上已有 6 個語意色, 剩下的空檔都靠近某個既有色。挑橘的理由是它跟會「疊在同一個物件上」的顏色離得最遠: 鑰匙會拿在可鉤發光(黃綠)的幽靈手上, 選綠色就會跟鉤爪光混成一團; 鎖立在門(洋紅)旁邊, 紫色會和門混。橘和紅、金只差 30° / 16°, 是相鄰色, 所以另外靠形狀分開: 尖刺是三角排、終點旗是帶星的旗面, 鑰匙一律是「圈 + 柄 + 齒」的鑰匙形, 鎖身上有掛鎖記號, 而且三者從不疊在同一個物件上。試玩若讀成「金色的鎖」, 優先把鑰匙色往紅橘調暗(明度再拉開), 不動危險紅與終點金。

## 形狀語言

圓角方塊角色、扁平無漸層的場景塊; 狀態靠「亮色 vs 暗色 + 實心 vs 虛線」切換; 「實心擋路」只有地面材質一種長相, 「會開的東西」(門、鎖)開著時一律只剩「虛線框 + 上下框頭」; 所有文字帶深色描邊。

## 理念落實

- P0: 玩家 = 實心奶白 + 深色外框; 幽靈 = 同一個剪影, 半透明淡藍 + 虛線外框; 危險只用紅; 每種可互動物件都有專屬色, 加一個專屬記號(開關鈕的箭頭 / 直條、鎖的掛鎖、翹翹板兩端的 ↓ / ↑)。
- P1: 最顯眼的是「現在可以鉤」(鉤爪色粗框)和瞄準箭頭; 路線、背景網格、升降台軌道都壓在低不透明度。牆用地面的暗色材質, 不搶門的亮洋紅。
- P2: 幽靈「只有頭頂可站」畫成頭頂一條實線(其餘外框是虛線); 升降台行程畫成背景上的軌道(只在第 4、6 關); 坑底有暗紅警示; 門與鎖開著時保留虛線框, 讓「之後會關 / 曾經擋路」看得到; 牆畫成實心, 讓「從門下繞不過去」看得到; 拿著鑰匙的人手上一定有實色鑰匙, 幽靈也一樣。
- P3: 鉤爪色只代表鉤爪系統, 鑰匙色只代表鑰匙與鎖; 開關與受控物件同色同記號; 「實心」= 地面材質(地面、牆共用); 「開著」= 虛線框 + 上下框頭(門、鎖共用); 說明頁、關卡卡片、解鎖頁、全破畫面裡的物件全部呼叫遊戲內函式, 並給規則上成立的 state。
- P4: 升降台與門的開關, 除了顏色, 鈕上的記號也不同(向上箭頭 vs 直條); 門與鎖同尺寸、相鄰, 除了洋紅 vs 橘, 關著時的紋路也不同(橫條紋 vs 三個掛鎖); 翹翹板落點端與發射端靠明度(暗 / 亮)加箭頭方向(↓ / ↑)分開; 玩家與幽靈靠不透明度加外框線型分開。
- P7: HUD 只放代數、關卡、已解鎖的能力、鑰匙格(只在第 6 關)、按鍵提示和靜音; 沒解鎖的能力整塊不畫, 不畫灰掉的佔位。角色身上只有一個小小的代數數字(回放時三代要分得開)。
- P9: 線類元素(路線、鉤索、瞄準線、箭頭)都有深色襯底, 過關回放三代同框時仍讀得到; 手上的鑰匙有深色外框, 疊在半透明幽靈或發光幽靈上照樣看得到。
- P13: 過關 / 失敗面板只有一塊, 不和其他事件疊。
- P15: 吹哨波紋(全場重要事件, 0.4 秒)是場上唯一的外擴大環; 鉤索只有 0.15 秒的細線; 翹翹板擺動只在發射端上方多三條短線。
- P17: 蓄力: 箭頭長度表示「會飛多遠」, 角色外圍的蓄力環表示「離滿還差多少」, 滿了環轉白。
- P18: 鉤爪次數、鑰匙有沒有拿到都常駐在 HUD; 代數用三個小人圖示常駐(上一代 = 幽靈樣、更早 = 消失的虛線、未來 = 空框)。
- P19: 可鉤提示直接長在幽靈本體上(框內粗框 + 染色), 不在旁邊另掛圖示; 鑰匙拿在角色手上, 不在頭上另掛標記。
- P21: 說明第 2 頁並排「跳不上(叉)」與「掉坑(勾)」; 第 5 頁畫出 2 號幽靈腳下那個看不見的 1 號虛線輪廓, 把「幽靈自己會飛」這個誤解和正確答案分開; 起跑哨解鎖頁並排吹哨前後, 舊位置留虛線輪廓。

### drawHud 細節(版位固定, 沒解鎖的區塊留空、不移位)

- x 470~650: 平時是「C 吹哨」(whistleUnlocked 時才有)、「R 重來」; **aiming=true 時換成鉤爪色「Z 彈出 / X 取消」框, 並在遊戲區四周畫冷色霧框 + 四角括號 + 右上暫停符號(時間停了)**
- 右上 x 672~708: 喇叭圖示(muted 時灰身 + 斜線)+ 下方 M 鍵帽

### 說明頁分工(drawGuidePage)

- **RD 傳 `{page, x, y, w, h}`(建議用這個)**: 美術只在 (x, y, w, h) 框內畫示意圖, 會裁在框內, 不畫背景、頁標題、說明文字、頁碼、翻頁提示。示意圖設計比例 640 × 760, 等比縮放置中進框(建議框 `x 40, y 300, w 640, h 760`)。圖內只有物件旁的短標籤(「你」「終點旗」「幽靈」「1 號」等)。
- **只傳 `{page}`**(interface.json 原寫法): 畫滿整張畫布, 含背景、標題、說明文字、示意圖(框 40, 280, 640, 760)、頁碼點(y 1120)、底部「空白鍵 下一頁 / 開始遊戲」。這時 RD 不要再畫任何字。
- 第 1 頁的 ←→ / 空白鍵 / R 鍵帽是 guide.md 指定「標在角色身旁」的圖內標示, 由美術畫在框內(角色右側), 角落的 M + 喇叭也是。**RD 畫頁面文字時不要再重畫這幾個鍵**; 頁底的「空白鍵 下一頁」照常由 RD 畫。

## 繪製層級(由下到上, RD 照這個順序呼叫)
