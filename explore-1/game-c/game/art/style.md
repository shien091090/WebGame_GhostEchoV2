# 三代接力 美術規格(style.md)

> RD 注意: `index.html` 必須宣告 `<meta charset="utf-8">`, art.js 內含中文字串。
> 載入方式: `<script src="art/art.js"></script>`(一般 script, 非 module), 之後用全域 `window.Art`。

## 邏輯畫布尺寸

720 × 1280(`Art.canvas`)。HUD 佔 y 0~100。

## 形狀語言

扁平幾何、圓角角色 + 直角場景、深色細描邊; 「實心 = 實體 / 可擋」「虛線 + 半透明 = 可穿過 / 幽靈」。

## 理念落實

- P0 辨識度先於好看: 角色與幽靈同一個身形, 但實心描邊 vs 半透明虛線; 尖刺是全畫面唯一的紅與唯一的三角形
- P1 視覺權重跟決策迫切度: 角色、開關壓住的亮光、門頂燈最亮; 背景格線 3.5% 白、地面中低明度; 過關/失敗字樣只在沒有即時決策的結束階段出現
- P2 規則上存在的東西畫面上就存在: 幽靈「只有頭頂可站」→ 幽靈全身半透明虛線, 只有頭頂一條全寬 40 的實心亮邊; 單向平台下半半透明 + 底緣虛線(從下可穿); 坑的底部露出暗紅(掉下去會死); HUD 的三代圖示照規則 9 顯示(更早的代淡到幾乎看不見、上一代是幽靈、未來是虛線空框); 所有物件畫在 interface 的 size 內, 畫面邊界 = 判定邊界
- P3 一個意義一種長相: 「亮琥珀 + 外光」只代表「開關壓住 / 門開」, 開關按鈕與門頂燈同時亮; 「虛線 + 半透明」只代表幽靈與可穿過; 幽靈與玩家用同一套身形與代色, HUD、說明頁直接呼叫遊戲內畫法
- P4 關鍵區分至少兩條通道: 玩家 vs 幽靈 = 不透明度 + 描邊線型(實/虛)+ 眼睛實心/空心 + 頭頂亮邊; 開關放開 vs 壓住 = 高度(凸起 10px / 齊平 5px)+ 明度(暗琥珀 / 亮琥珀外光); 門關 vs 開 = 實心門板 / 只剩虛線框 + 頂燈暗 / 亮
- P7 每個元素都要掙得版面: 角色身上不放代數數字(代色 + HUD 已足夠); HUD 只放代數與按鍵, 無計分
- P9 以最混亂的那一刻驗收: 過關回放時三代幽靈 + 門與開關同時動作, 三代色色相與明度都拉開, 頭頂亮邊用各自代色, 疊在一起仍分得出是誰
- P13 事件排隊: 同一時間只有一個事件字樣(倒下橫幅 / 過關面板 / 失敗面板, 依 phase 互斥)
- P15 回饋強度與份量成正比: 倒下 = HUD 下方細橫幅; 過關 = 中央大面板(不壓關卡區); 失敗 = 全畫面壓暗 + 面板
- P17 進度類資訊: 代數用「第 N / 3 代」數字給精確讀數, 三格圖示給「誰還在場、誰消失」(數字給不了的那一段)
- P18 重要資訊不能只存在一瞬間: 現在第幾代、哪一代已消失常駐在 HUD
- P19 資訊貼著物件: 「門開了」顯示在門本身(頂燈 + 門板收起), 不另掛標籤
- P21 示意圖選分岔例: 說明第 3 頁並排「一般跳差一截 ✗」與「踩幽靈頭上得去 ✓」; 第 4 頁並排門關 / 門開兩格

## 物件表

所有 x / y 為物件左上角(與 interface.json 一致)。每個函式自己 save/restore。

| 物件 | 函式 | state 欄位 | 各狀態視覺 |
|---|---|---|---|
| 背景 | `drawBackground(ctx)` | — | 深藍漸層 + 40px 細格; 最下緣 70px 暗紅漸層(只在坑露出) |
| 平台 | `drawPlatform(ctx, {x, y, w, h})` | x, y, w, h | **h ≥ 40 畫實心地面**(磚紋 + 8px 亮頂面); **h < 40 畫單向平台**(6px 亮頂面 + 半透明直條下半 + 底緣虛線)。地面傳 h=80、平台傳 h=24 即可 |
| 尖刺 | `drawSpike(ctx, {x, y, w})` | x, y, w | 單一外觀: 紅三角一排(每 20px 一根), 高 24 |
| 開關 | `drawPlate(ctx, {x, y, pressed})` | x, y, pressed(布林) | false: 暗琥珀按鈕凸起佔滿 12px 高 + 斜紋; true: 按鈕齊平只剩底部 5px、亮琥珀 + 外光 |
| 門 | `drawGate(ctx, {x, y, open})` | x, y, open(布林) | false: 實心門板 + 橫柵 + 外框, 頂燈暗琥珀; true: 門板收到頂端 24px, 其餘只剩淡琥珀虛線框 + 向上小箭頭, 頂燈亮琥珀外光 |
| 終點旗 | `drawGoal(ctx, {x, y})` | x, y | 單一外觀: 旗桿 + 黑白方格旗(微飄動) + 白色外光 |
| 幽靈 | `drawGhost(ctx, {x, y, facing, state, gen})` | x, y, facing(1/-1), state(idle/run/air), gen(1~3) | 代色 28% 半透明身體 + 代色虛線輪廓 + 空心眼; **頭頂一條 40×6 實心代色亮邊 = 唯一可站處**; 腿: idle 並立 / run 兩幀交替(110ms) / air 收腿; 眼睛偏向 facing |
| 玩家 | `drawPlayer(ctx, {x, y, facing, state, gen})` | x, y, facing(1/-1), state(idle/run/air/dead), gen(1~3) | 代色實心身體 + 深色描邊 + 實心眼; idle/run/air 腿同幽靈; air 時瞳孔上移; **dead: 身體灰、描邊改代色、眼睛變 X、雙腿外張** |
| HUD | `drawHud(ctx, {gen, maxGen, phase})` | gen, maxGen, phase(play/dying/win/lose) | 見下 |
| 說明頁 | `drawGuidePage(ctx, {page})` | page(0 起算, 0~4) | 自帶背景, 整頁覆蓋畫布; 底部提示「空白鍵 下一頁」, 最後一頁「空白鍵 開始遊戲」 |

另匯出 `Art.guidePages = 5`(說明頁總頁數, RD 可用來判斷最後一頁)。

### HUD 各 phase

- 共通: y 0~100 深色底帶; 左「第 gen / maxGen 代」(代色); 其右三格縮小角色: 比上一代更早 = 幾乎透明的幽靈、上一代 = 幽靈、本代 = 實心角色、未來 = 虛線空框; 右側兩行按鍵提示
- play: 只有上述
- dying: 本代圖示換成死亡外觀; y 124~172 中央小橫幅「倒下了…第 N 代準備出生」(最後一代只寫「倒下了…」)
- win: 三格都畫成幽靈; y 170~420 中央面板「過關! / 三代接力回放中 / 按空白鍵重來」, 位於關卡區上方空白, 不擋回放
- lose: y 100 以下全畫面壓暗 + y 480~760 面板「失敗 / 三代都倒下了 / 按空白鍵重來」

### 繪製層級(由下而上)

drawBackground → drawPlatform(全部) → drawSpike → drawPlate → drawGate → drawGoal → drawGhost(全部) → drawPlayer → drawHud。
開關要畫在平台一之後(嵌在平台上)。過關回放時不畫 drawPlayer, 三代都用 drawGhost。
